# 上車前速查

第一次帶這個 App 接真車時看這一頁就夠。寫給站在車旁邊、手上只有手機的人。

---

## 出發前（在家做完）

1. **只有 Bluetooth Classic 轉接器要先在系統藍牙設定完成配對。** App 不能替
   Classic 發起配對；多數配對碼是 `1234` 或 `0000`。盒子上寫 BLE、4.0 或 5.0
   的轉接器**不要配對**，到 App 裡選 Bluetooth LE 掃描即可。
2. 手機裝好 field build。從 GitHub Releases 下載時，檔名是 `telltale-v*.apk`，
   使用 **community key** 簽署；Google Play 安裝則是另一條簽章線。兩者不能互相
   覆蓋更新。切換前先在 App 內匯出紀錄，再解除安裝；解除安裝會刪除 App 本機資料。
3. 打開 App → **Demo 模擬器 → 啟動模擬器**，確認儀表板會動、故障碼能掃。
   這一步不需要車也不需要轉接器，用來確認 App 裝好了、畫面會動。

   **但它證明不了到車上就會順。** Demo 完全不經過藍牙、不經過真實 socket、
   不做通訊協定協商、不驗 checksum，也沒有多個控制器。這些正是最容易出問題
   的地方。所以在車上遇到狀況時，不要因為 Demo 是好的就認定問題一定在轉接器
   或車上 —— **把紀錄匯出帶回來**，那才分得出來。

4. *（想更保險的話）* 在電腦上跑一個假的轉接器，讓手機用 Wi-Fi 連過去。這會
   走真的網路、真的 socket、真的協定協商，比 Demo 接近上車：

   ```bash
   python3 -m venv /tmp/elmvenv
   /tmp/elmvenv/bin/pip install setuptools==80.10.2 wheel==0.45.1
   env -u GITHUB_RUN_NUMBER /tmp/elmvenv/bin/pip install \
     --no-build-isolation ELM327-emulator==3.0.5
   /tmp/elmvenv/bin/pip check
   # -b 是必要的：沒有批次檔，這個 CLI 的 stdin 一 EOF 就自己結束
   /tmp/elmvenv/bin/python -m elm -n 35000 -s car -b /tmp/elm_batch.out &
   ipconfig getifaddr en0
   ```

   最後一行印出的就是手機要連的位址：App → Wi-Fi → `<那個 IP>:35000`
   （35000 是這個模擬器的預設埠，也是 App 的預設埠）。

   它讀得到車身號碼、儀表會動；但它不會回故障碼，那是它自己的限制，不是
   App 壞掉。

## 到車上

**先開電門，不要發動引擎。** 轉接器要有電才會被看到，而且多數控制器在引擎
運轉時不會清除故障記憶。

1. 轉接器插上 OBD 埠（駕駛座下方，方向盤左下或中控下緣）。
2. App → 如果不確定該選哪一種連線，點連線畫面最上面的 **「不確定要選哪一個？」**
   —— 它問三個看得見的問題（Wi-Fi 清單有沒有多一個網路、盒子上有沒有寫
   BLE／4.0／5.0、是不是舊款 2.0／3.0），不用管 SPP、GATT 這些名詞。
   **盒子上寫 BLE 或 4.0／5.0 的一律選 Bluetooth LE，不要去系統設定裡配對它**
   —— 這種轉接器雖然會出現在藍牙配對清單裡，但配對這條路走不通。
3. 選好之後從清單挑轉接器。

### 已配對清單裡都是耳機怎麼辦

那是正常的 —— 清單來自手機，不是 App，所以耳機、車機、筆電都在裡面。看起來
像轉接器的（`OBDII`、`OBDLink`、`Vgate`、`V-LINK`、`ELM327`…）會排在前面。

**選錯了就按「取消」，不必等它自己失敗。** 取消後可以馬上改選別的。

取消只能停在「目前這一步」—— 藍牙的連線嘗試一旦交給系統就沒辦法中斷，所以
上一個嘗試最多還會再跑十二秒才收尾。如果你在這段時間內改選了別的裝置，畫面
會顯示 **「正在中止上一個連線，請稍候…」** 並帶著你剛選的裝置名稱，那是正常
的，等它自己接上就好。真的等太久（二十秒）才會出現「上一個連線仍在中止中」，
這時隔幾秒再點一次就行。

### 如果你用 Wi-Fi 轉接器：第一次接上時，注意那個系統詢問

轉接器的熱點沒有網際網路。**第一次連上它的時候，Android 會問你「此 Wi-Fi 無法
連上網際網路，是否繼續使用？」——選「保持連線／仍要使用」。** 那是一次性的，選過
之後 Android 會把這個網路記成「使用者接受未驗證」，以後就不再問，也不再想切走。

這一段是**實測過的**，不是推論。做法是在這支手機上把 Android 的網路驗證探測指向
一個不可路由的位址，讓家裡的 Wi-Fi 被判定成「沒有網際網路」，同時開著行動數據
(ping 8.8.8.8 確認行動數據真的通)，然後用 App 連一台真的 ELM327 模擬器：

- 手機的預設網路**仍然是那個 Wi-Fi**，沒有切到行動數據。
- App 正常連上、80 PIDs/s、故障碼／VIN／凍結幀全部讀到。
- 原因在系統紀錄裡看得到：那個網路帶著 `acceptUnvalidated` 旗標 —— 因為以前有人
  對它答過「仍要使用」。

**所以真正的關鍵是那個詢問，而不是行動數據本身。** 一個從沒接受過的新熱點才是
沒有旗標的狀態，而轉接器的熱點對你的手機來說就是新的。

如果你錯過了那個詢問，或它沒有出現：

| 做法 | 性質 |
|---|---|
| 設定 → 連接 → Wi-Fi → ⋮ → 智慧 Wi-Fi → 關掉「切換到行動網路」 | 一次性 |
| 關掉行動數據(下拉快捷設定) | 每次都要，最後手段 |

**還是連不上就把紀錄匯出**(設定 → 診斷紀錄 → 匯出)。裡面看得到連線停在哪一步。

### 連不上的時候

失敗訊息底下會列出三種連線方式各自的結果（加密 SPP / 未加密 SPP / 直接連
通道 1）。三種都試過才會宣告失敗。

按 **「匯出紀錄」** 把這次往返的每一個位元組帶回來 —— 比畫面上那一句話有用
得多。含十六進位的版本更完整，檔案大一點。

其他常見原因，照順序試：

**兩個最常見的原因，先排除它們**（來自 Car Scanner 官方的排障清單，它們的
使用者量比我們大三個數量級）：

1. **選錯裝置。** 這是他們列的第一名 —— 使用者從清單裡挑到車機、耳機或別的
   東西。我們的清單會把看起來像轉接器的排前面，而且會記住你上次用的那台，
   但清單本身還是手機給的。
2. **轉接器壞了。** 這是他們標註「最常見」的一項。同一顆轉接器插到別台車、
   或用別的 App 試一次，是最快的分辨方法。

| 現象 | 先試這個 |
|---|---|
| 完全找不到裝置 | 電門有沒有開？轉接器上的燈有沒有亮？ |
| 連上但沒有讀數 | 引擎發動看看 —— 有些車電門 ON 不供電給 OBD 埠 |
| 連線後幾秒就斷 | 轉接器鬆了，往裡壓緊 |
| 一直逾時 | 拔掉轉接器等十秒再插回去，然後重開 App |

## 讀數

儀表板上方那一排是連線體質：**PIDs/s**（每秒讀幾個值）、**fastMode**（有沒有
在批次查詢）、**電壓**。

- 電壓在引擎沒發動時應該是 12.0–12.8 V；發動後 13.5–14.5 V。低於 12 V 而且
  車發不動，多半是電瓶。
- PIDs/s 掉到個位數通常是轉接器品質問題，不是車的問題。
- 灰掉的儀表代表那個 PID 這台車沒有或這次沒讀到 —— App 會過幾分鐘自己再問
  一次，如果車其實答得出來，數字會自己回來。

**推算數值**（馬力、扭力、油耗）用的是「設定」裡的車輛參數。排氣量、車重、
容積效率填得越接近實車，這幾個數字才有意義；沒填就只是個相對趨勢。

## 先花一分鐘確認轉接器沒在騙你

App 能檢查轉接器**對自己的描述**有沒有矛盾（結果寫在匯出的紀錄檔開頭），
但它**沒有辦法知道轉接器報回來的數字是不是真的**。要確認那個，只能拿第二個
獨立的量測去對。

上車連上之後，趁還沒開始診斷，做這五個對照。每個十幾秒：

| 對照什麼 | 應該看到 | 不對勁的樣子 |
|---|---|---|
| **電壓**（引擎熄火 → 發動） | 12.0–12.8 V → 13.5–14.5 V | 兩種狀態下數字一模一樣 |
| **水溫**（冷車剛啟動） | 從接近氣溫開始，慢慢往上爬 | 一連上就是 90 幾度不動 |
| **進氣溫度**（車停一夜） | 接近當下的環境氣溫 | 跟氣溫差很多，或永遠固定 |
| **轉速**（踩一下油門） | 跟著引擎聲一起上下 | 不動，或動得跟聲音對不上 |
| **車速**（開起來，看儀表） | 比儀表板**略低** 1–3 km/h | 完全一樣、差很多、或不動 |

車速那一條值得解釋：儀表板依法規不得低報，所以原廠會刻意調高一點；OBD 讀到的
是比較接近真實的值。**App 比儀表慢一點是正常的，一模一樣才可疑。**

任何一項不對，**先不要相信畫面上的數字**，把紀錄匯出帶回來。

（順帶一提：Elm Electronics 這家原廠 2022 年就收了，市面上流通的 ELM327
幾乎都是仿製品。**這不代表它不能用** —— 大多數都能用。只是它對自己說的話
不能盡信，所以上面這些對照才有意義。真的要買好一點的，找 OBDLink 或
vLinker 這類會回報 STN 晶片的。）

## 故障碼

**掃描** 會讀三類：Mode 03 已儲存、Mode 07 待確認、Mode 0A 永久。每一筆都會
標出是哪一個控制器（`7E8`、`7E9`…）回報的。

### 看懂結論那一行

| 畫面說 | 意思 |
|---|---|
| 已回應的控制器都沒有故障碼 | 有回覆的模組都說沒事。**不代表車上每個模組都被問到了。** |
| 部分未確認 | 有些類別讀不到，結論不完整 |
| 無法確認 | 不要當成「沒問題」 |

如果儀表板的故障燈亮著而 App 說沒有故障碼，**相信儀表板**，並把紀錄匯出。
這通常代表有個控制器在閘道後面，功能定址問不到它。

### 凍結幀 —— 有故障碼的時候一定先看這個

有故障碼時，掃描結果最上面會多一張 **「故障發生當下的車況」**：控制器在確認那
個故障的那一瞬間記下的轉速、水溫、負荷、進氣溫度、燃油修正等等。

這是全 App 唯一一份「故障正在發生時」的資料。其他所有數字都是車子**現在**的
狀態 —— 停在原地、問題多半沒在發生。修車真正有用的是前者。

- 卡片標題會寫是**哪一個故障碼**造成的。三個故障碼只會有一份凍結幀，配錯會讓
  你去查錯的零件。
- 沒看到這張卡片，而且**畫面沒有出現「這次沒有讀到凍結幀」**，才代表這個控制器
  沒有存凍結幀（或它不支援 Mode 02）。這不是壞事，也不代表車況正常 —— 只是沒有
  這份資料。
- 如果出現 **「這次沒有讀到凍結幀 —— 不代表車上沒有」**，那是**讀取失敗**：逾時、
  轉接器沒回應、或掃描時間用完。車上很可能是有的。**先重新掃描，不要先清除** ——
  清除會把那份還沒讀到的紀錄永久銷毀。
- 底下如果寫「另有 N 個項目…沒有對應的換算公式」，表示凍結幀裡還有 N 個數值，
  車子有回報但本 App 不知道怎麼換算，所以沒列出來。專業掃描工具會多顯示那幾項。
- 如果寫「有 N 個項目這次沒有讀回來」，那是**讀取失敗**不是 App 的限制 —— 通常
  是掃描時間用完，或那個控制器當下沒回應。**重新掃描一次**多半就有了。這兩句話
  意思不一樣：前者重掃也不會變，後者會。

**清除故障碼會把凍結幀一起銷毀，而且故障再次發生前讀不回來。** 所以順序是：
先看凍結幀 → 匯出紀錄 → 再決定要不要清。

### 排放就緒狀態

故障燈那張卡片底下的一排晶片，是各個排放監控項目的完成狀況：`✓` 已完成、
`…` 未完成、`—` 這台車沒有這一項。

如果出現 **「未知監控項目」** 的晶片，代表這台車回報了一個本 App 沒有名字的
監控項目。這只可能發生在柴油車上（汽油車那八個位元本 App 都有名字）。它照樣
會算進「還有 N 項沒有完成」—— 叫不出名字不等於可以當作已完成。

`汽油微粒濾清器（GPF）` 這一項，很多網路上的 OBD 對照表寫成「空調冷媒」。
那是錯的：這個位元在 J1979 裡長年保留未定義，近年才定為 GPF。新款缸內直噴
汽油車才會有。

### 清除

**清除會重置排放就緒狀態。** 車子要重新跑完一輪自我診斷才能過驗車 —— 通常
是幾天的正常駕駛。驗車前不要隨便清。

清除後畫面會留下結果，不會自己消失。照它說的做：

| 畫面說 | 該做什麼 |
|---|---|
| 已送出清除指令 | 好了，會自動重新掃描 |
| 已有控制器回報清除完成，但無法確認其餘控制器 | **不要再按一次。** 重新掃描看結果 |
| 已有其他控制器完成清除，所以不要再送一次全車清除 | **不要再按一次。** 重新掃描看結果 |
| 清除指令已送出，但回應在傳輸過程中損毀 | **不要再按一次。** 重新掃描看結果 |
| 清除指令送出後連線中斷 | **不要再按一次。** 重新連線後掃描確認 |
| 轉接器不支援顯示回應標頭…不要直接再清除一次 | **不要再按一次。** 有東西被清掉了，只是不知道是誰 |
| ECU 已接受清除指令但尚未回報完成 | 等幾秒，重新掃描 |
| 拒絕清除，因為目前的車輛狀態不允許 | 電門轉到 ON、**引擎熄火**，再試 |
| 不支援清除服務（Mode 04） | 這個控制器要原廠設備才能清 |
| 要求先通過安全認證才允許清除 | 這個控制器要原廠設備才能清 |
| 目前忙碌中 | 等幾秒再試 |
| 拒絕清除（原因碼 0x…） | 車廠自訂的拒絕原因；把這個代碼連同紀錄一起帶回來 |
| 清除指令還沒送出就失敗了 | 指令根本沒上線，直接再試 |
| 清除失敗，沒有控制器接受指令 | 轉接器不認得這個指令，可以再試 |

**按鈕就是這一次清除的結論。** 只要有任何控制器可能已經清掉了，「清除」就會
變成灰色的「請先重新掃描」—— 因為重複送全車清除會讓已完成的控制器再重置一次
就緒狀態，白白多花一個駕駛週期。反過來，按鈕還能按就代表**這一次**什麼都沒被
清掉，直接再試一次是安全的。訊息叫你再試一次的時候，按鈕一定能按。

**重新掃描之後，按鈕會回來，這時它就不再是上一次的結論了。** 掃描結果本身才
是。上面那句警告會換成「上一次清除的結果無法完全確認，以下是重新掃描後的實際
狀況」，提醒你先前確實清掉過東西 —— 再按一次仍然會重置那些已完成的控制器，
只是這次你是看著新的掃描結果做決定，不是盲目重送。

## 帶回來什麼

不論順不順利，**設定 → 診斷紀錄 → 含十六進位**。匯出的「Telltale 實車證據
v1」會自動帶上：

- App 版本、手機型號、Android／SDK 版本與 UTC 工作階段時間；
- 當下已設定的排氣量、車重、容積效率、燃料與驅動方式；
- 連線種類、轉接器名稱／識別碼或 Wi-Fi 位址；BLE 另含掃描 RSSI、MTU 嘗試、
  實際服務／特徵 UUID 與 notify／indicate；
- 轉接器回報、協定、ATDPN、匯流排型態，以及原始 OBD 往返資料。

真實轉接器連線期間，可在同一區的 **「實車事件標記」** 按「電門 ON」、
「引擎發動」、「輕踩油門」或「道路測試開始」；Demo 會停用這些按鈕。每次按下
都會把事件放進原始資料的同一條時間軸並立即嘗試保存，若只能留在記憶體會明確
提示立刻匯出。**只在車輛完全停妥時操作，行進中交給乘客。** App 進入背景、
回到前景、使用者中斷與轉接器意外斷線則會自動標記。

長時間連線達到容量上限時，App 會保留開頭 200 筆握手與最新資料，並在中間明確
標出捨棄筆數與時間範圍；不會把截斷紀錄假裝成完整紀錄。任何「讀不到、判斷不
出來」的狀況，這份檔案比任何描述都有用。

**這是原始診斷證據，不是匿名報告。** Mode 09 回覆可能含 VIN，檔頭也可能包含
轉接器或手機識別資訊。App 不會主動上傳到服務端；系統備份是否包含 App 文件則依
手機設定。只有你主動開啟分享單才會傳給所選 App；公開貼出前先確認內容。

分享單跳出來之後，**選 Gmail、雲端硬碟，或任何會收附件的 App**。三星
「快速分享」裡那個**「儲存」不要按** —— 它是 Quick Share 的存連結功能，不收
檔案，會回你「無法儲存文字，建議改為儲存連結」。這是那個按鈕的限制，不是匯出
失敗；同一次分享送到 Gmail 是一個 176 KB 的 `.txt` 附件，正常得很。
（實測：Galaxy S24 Ultra，One UI 快速分享。）

### App 自己死掉的話

正常前景連線時，App 每 30 秒會嘗試自動存一份到手機上。若最近一次保存成功，
App 當掉、被系統關掉或手機沒電後，通常只會少掉約最後 30 秒；系統延遲排程或
儲存失敗時可能更多。下次打開 App，連線畫面最上面會出現「上一次連線的紀錄」，
按「匯出」一樣送得出來，檔名會多一個 `-recovered` 讓你分得出來。

那份自動存的紀錄只有一份，會被下一次連線覆蓋 —— 但**模擬器的紀錄永遠不會蓋掉
真車的紀錄**。所以車上出了狀況、回家想確認 App 有沒有壞而點了 Demo 模擬器，
車上那份還在。

App 無法自動記下轉接器外殼／LED、儀表板畫面或你聽到的異音；這些仍請拍照、
錄影，並記住異常發生的大約時間。若有帶電腦，`adb logcat` 是額外證據，不是匯出
檔的替代品。

「手動指令」只接受唯讀查詢（`ATI`、`ATDPN`、`ATRV`、`0100`、`03` 之類）。
清除故障碼不能從這裡送 —— 那個要走故障碼畫面的按鈕，所有安全檢查都在那裡。
